# MR Workshop first increment

Shane authorized a separate active mixed reality workshop, then a holographic console if the workshop is solid, and communication with the existing procedural asset generator when identified. Execution is autonomous under that direct authorization; no repeated approval gates. Focus remains preserved.

The standalone `MRWorkshop` Unity project shares pinned Unity6000.3.25f1 / Meta207 / OpenXR1.17 / XRHands1.7.2 / URP17.3 dependency versions and tracked configuration, not Focus runtime or its Library. Package identity is `com.thegamingdonkey.mrworkshop`. It has its own scene, save/runtime domain, output APK and project MCP identity. No room recognition, MRUK, networking or external model service is needed for this increment.

The visible workbench has a power cell, cube and orb, a powered rotor, a typed power socket and a control panel. Users can grab and release objects through official SDK hand/controller interactions. Floating objects use no gravity to avoid dropping through unmodelled real furniture. A cell snaps only after the last selecting pointer releases it within0.14m of the empty socket. Wrong shapes and occupied sockets reject; cancellation never docks. Grabbing an attached cell undocks it. Transform controls refuse held or docked parts. Resize stays within0.75–1.5 of authored scale; rotation is15degrees. Reset is refused while any object remains held, avoiding forced grab conflicts, and returns released objects to their home poses while clearing ownership and power. Headset tracking loss cancels dock attempts and stops powered motion; recovery starts fresh.

Desktop mode must be honestly labelled and usable with mouse and keyboard: select/drag on a workbench-parallel plane, release to dock, R rotate, +/- resize, Space toggle power, Escape cancel, Reset button. This mode uses the same object/controller/socket logic, but never establishes physical hand tracking or passthrough. A finite diagnostic separately exercises docking/rejection/undocking/power/reset. A visible Editor demo and screenshots, fresh meaningful domain/Unity tests, one APK build and one package check are the acceptance evidence. Preserve unique outputs and never stop unrelated applications. Critic gets one bounded final review; repeat checks only after a failure or diagnosed code change.

Procedural geometry is the usable baseline. Optional generator assets must be original small Unity-ready FBX/GLB props in metres, simple materials, no rigs needed, and must not change colliders or interaction semantics. Console is the next milestone, not an excuse to prolong this one.
